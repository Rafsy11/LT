# AGENT.md — Architecture & Engineering Rules (ISP Field Ops & Master Data System)

You are an expert Full-Stack TypeScript Engineer working on an enterprise **On-Premise ISP Field Operations, Network Master Data, & FTTH Monitoring System**.
Every line of code you write MUST strictly adhere to the architectural boundaries, data integrity laws, and security guardrails defined in this document.

---

## 1. Project Overview & Core Domain
- **System Role:** Single Source of Truth (Master Data) for FTTH Network Inventory (`Cluster` -> `ODP/Splitter` -> `Port`), Customers (`SIA`), Field Work Orders (`Tickets`), Real-time Attenuation Monitoring, and an On-Premise Agentic AI Assistant.
- **Scale & Environment:** Deployed 100% On-Premise (Docker Compose behind Nginx). Serves ~200 concurrent field technicians via Mobile App and multiple Admins/NOC via Web Dashboard.
- **Strict Workflow Law:** Technicians CANNOT create or edit customer/network master data freely. All field submissions MUST be bound to an active `Ticket` (`PSB` for new installation or `MAINTENANCE` for assurance) dispatched by an Admin.

## 3. NON-NEGOTIABLE Architectural Laws (CRITICAL)

### Law 1: NEVER Put Core Business Logic Inside Next.js Server Actions
- **Why:** The React Native mobile app cannot invoke Next.js Server Actions.
- **Rule:** Write all business logic, validation, and database transactions inside `apps/web/src/services/*.service.ts`.
- **Exposure:**
  - Expose endpoints to React Native (and Web) via REST Route Handlers in `apps/web/src/app/api/v1/**/route.ts`.
  - Web Server Components or Server Actions may call the `services` layer directly, but must never contain raw ORM queries or duplicate validation logic.

### Law 2: Immutable History & Server-Side Timestamps Only
- **Why:** Technicians can manipulate their phone clock (`Clock Skew`) or attempt to falsify historical attenuation logs.
- **Rule:**
  - `attenuation_histories` and `activity_logs` are **APPEND-ONLY** tables. NEVER generate `UPDATE` or `DELETE` queries for these tables.
  - Technicians only input *current* measurements. History and audit logs are automatically generated inside the backend database transaction upon ticket submission.
  - All primary timestamps (`created_at`, `completed_at`, `updated_at`) MUST be generated by PostgreSQL (`DEFAULT NOW()`). Device timestamps from React Native may only be stored in a separate metadata column (`client_recorded_at`).

### Law 3: Idempotency & Concurrency Locking on Ticket Submission
- **Why:** Unstable cellular networks cause duplicate retries; concurrent submissions can double-book the same physical splitter port.
- **Rule:**
  - Every ticket submission from React Native MUST include a client-generated UUID v4 `submission_id` (`X-Idempotency-Key`).
  - Before processing a submission, check if `submission_id` already exists in `attenuation_histories`. If it exists, return the existing success response immediately without re-executing the transaction.
  - All splitter port assignments (`splitter_id` + `port_number`) MUST execute inside an interactive database transaction (`prisma.$transaction` / `db.transaction`) and respect the PostgreSQL partial unique index:
    `UNIQUE (splitter_id, port_number) WHERE status = 'ACTIVE'`.

### Law 4: Dual-Auth, Cluster Scoping (RLS), & Hierarchy Protection
- **Auth Mechanism:**
  - Web Admin uses `HttpOnly, Secure` cookies.
  - Mobile Technician uses `Authorization: Bearer <short_lived_jwt>` + Refresh Token stored in `user_sessions` (bound to `device_id`).
  - Checking session validity MUST verify that the user (`is_active === true`) and session (`revoked_at IS NULL`) are active so Admins can force-logout technicians instantly.
- **Role Editor Protection:** Users cannot grant permissions they do not possess, nor can they modify users with an equal or higher `hierarchy_level`.
- **Cluster Scoping:** Every query executed by a non-Super Admin (including via AI Chatbot) MUST automatically filter by `user.assigned_clusters`.

### Law 5: File Uploads & Environment Variables in Next.js
- **No Local File Storage:** NEVER save uploaded OPM/ODP photos to the Next.js local filesystem (`public/`). Always upload to **MinIO** (S3-compatible object storage) using Presigned URLs and store only the `object_key` in PostgreSQL.
- **No Hardcoded `NEXT_PUBLIC_` URLs:** Web frontend API calls must use relative paths (`/api/v1/...`) so Docker images remain portable across staging and on-premise production environments.

## 4. Mobile App (React Native) Engineering Rules

1. **Anti-Fake GPS & Geofencing:**
   - Always inspect `location.mocked` (Android) from `expo-location`. If `true`, block form submission immediately.
   - Calculate the Haversine distance between the technician's current coordinates and the target `network_splitters` coordinates. Flag or block submissions exceeding the configured radius threshold.
2. **In-App Camera & Image Compression:**
   - Disable gallery image picking for OPM/attenuation proof. Force capture via `react-native-vision-camera`.
   - Compress photos on-device using `expo-image-manipulator` (max width `1280px`, quality `0.7`, JPEG/WebP, target size `< 300KB`) before uploading to MinIO.
3. **Offline-First Queue:**
   - Persist assigned tickets and pending form submissions locally using `MMKV` or `expo-sqlite`.
   - Keep the original `submission_id` (UUID) intact across automatic background retries when network connectivity returns.
4. **App Version Gate:**
   - Attach header `X-App-Version` to all API requests. Handle `HTTP 426 Upgrade Required` globally by locking the screen and prompting an APK/OTA update.

## 5. Real-Time Monitoring (SSE) Rules

- Use **Server-Sent Events (SSE)** at `GET /api/v1/admin/stream/reports` powered by **Redis Pub/Sub**.
- Every SSE response MUST include these exact headers to prevent Nginx reverse-proxy buffering:
  ```typescript
  {
    'Content-Type': 'text/event-stream',
    'Cache-Control': 'no-cache, no-transform',
    'Connection': 'keep-alive',
    'X-Accel-Buffering': 'no'
  }
  ```
- Classify attenuation (`dBm`) status consistently across shared constants:
  - `NORMAL` (Green): `-15.0` to `-22.0 dBm`
  - `WARNING` (Yellow): `-22.1` to `-25.0 dBm`
  - `CRITICAL` (Red): `< -25.0 dBm` (worse than -25 dBm) or `> -10.0 dBm`

## 6. On-Premise Agentic AI Chatbot Guardrails

We run a local LLM (e.g., `Qwen 2.5 Instruct` via Ollama/vLLM) integrated with the **Vercel AI SDK (`streamText` + `tools`)**.

1. **NO Raw Text-to-SQL:** Never allow the LLM to generate or execute raw SQL strings. The LLM may only interact with the system through strictly typed Zod tools defined in `apps/web/src/ai/tools/`.
2. **RBAC Context Injection:** Never pass `user_id`, `role`, or `allowed_clusters` via the LLM prompt where they can be manipulated via prompt injection. Inject the authenticated Admin's session context directly inside the server-side tool `execute` closure.
3. **Strict Split Between READ and WRITE Tools (Human-in-the-Loop):**
   - **Read Tools (`get_*`):** Execute database queries automatically (always enforce `LIMIT <= 50` and cluster scoping) and return structured data to the LLM.
   - **Write/Mutating Tools (`prepare_*`):** NEVER mutate the database inside an AI tool call. Write tools must ONLY validate parameters (e.g., check if SIA exists, check if splitter port is free) and return a **Confirmation Payload** (`requires_confirmation: true`, `action_type`, `payload_summary`, `signed_action_token`).
   - Actual database mutation only happens when the Admin clicks the **[Approve & Execute]** button on the UI, which calls `POST /api/v1/admin/ai/confirm-action`.

## 7. Coding Conventions & Error Handling

- **Strict TypeScript:** `strict: true` everywhere. Never use `any` or `@ts-ignore`.
- **Single Source of Validation:** Define all request/response payloads in `packages/shared/src/schemas/*.schema.ts` using **Zod**. Import those exact schemas into both Next.js API routes and React Native forms.
- **Standardized API Response Envelope:**
  ```typescript
  type ApiResponse<T> =
    | { success: true; data: T; meta?: Record<string, unknown> }
    | { success: false; error: { code: string; message: string; details?: unknown } };
  ```
- **Database Migrations:** Never run `prisma db push` in production scripts. Always generate explicit SQL migration files (`prisma migrate dev` locally, `prisma migrate deploy` in production) and include custom SQL indexes (such as the partial unique index for active splitter ports).
